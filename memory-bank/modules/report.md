# Module: Report
`components/report/ReportPages.tsx` renders 3 pages:
1. Page 1: Official NCERT report sheet table (`S. No.`, `Sub-Test`, `Score Obtained`, `Sten Score`, and `Performance` sub-columns `High | Average | Low` with `✓`), exact norm table citation (`Appendix IV / V, Table 1–6`), and `APTITUDE PROFILE` Sten chart.
2. Page 2: Meaning of each score (Appendix VI). Subject and field recommendations are shown ONLY for **High** scores (`Sten 8–10`) and **Average scores close to the High bracket** (`Sten 7` / within 2 marks of High's lower cutoff). No recommendations are shown for other Average (`Sten 4–6`) or Low (`Sten 1–3`) scores.
3. Page 3: Suggestions/Remarks (including performance summary by band, Section 5 p. 11 counselling & self-exploration remarks when no High score is obtained, Appendix VII occupations for High and near-High scores only, bold p. 12–13 caution notice, and Teacher's Signature).
Individual report routes fetch an explicit name-free student projection once on the server, then render `ReportDialog`. The dialog defaults to Hindi on every opening and has a top-corner Hindi/English selector. All three pages, chart labels, descriptions, recommendations, remarks, citations, and printing follow the selected language. Typed local translations live in `lib/tamanna/report-language.ts`; no translation service receives student data. Names and name placeholders are absent from report props, content, headers, titles, bulk reports, and print output. Roll numbers remain.

Print CSS in `globals.css` expands the modal outside its scroll container and fixes each page to A4 portrait for a three-page PDF, including when printing from a narrow viewport. Page 2 and 3 include small italic source labels and color-coded icon cards. The Sten chart is an inline SVG tuned for print legibility; its band legend sits below the plot to avoid covering bars. Missing or uncertain scores and excluded sheets do not produce final Sten interpretations. Bulk printing retains English and omits names. Routes: `/admin/students/[id]/report`, `/admin/reports?class=IX`. Only booklet content may appear (see `booklet-source.md`).

Report dialogs are capped at 820px, close to the paper width. Meaning/remarks text is 14px on screen, with 10.5pt print body and 10pt recommendations. Meaning cards share the page height; the score table/chart are larger and the remarks signature sits at the bottom. Print pages use the available A4 height without hiding overflow.

The admin `@report` slot intercepts client report navigation and leaves the originating page mounted. Closing uses history back, preserving results filters, pagination, scroll, and focus; direct URLs use the normal server page and replace with results on close. `StudentReport` shares the single name-free server query between both entry points. Catch-all/default slot pages prevent stale overlays. Printing an intercepted report hides the underlying `.admin-page`.

`check:report` validates both languages, complete translation coverage, privacy, pending/excluded interpretation guards, and three report sections. It can write synthetic dense-report HTML fixtures to an explicit output file for local browser print checks.

Reports are available only after all seven final scores are saved on a non-excluded sheet with a current-key latest submission. Results/detail Report links share `reviewComplete` with the green OMR action. Direct/intercepted URLs render a Hindi review prompt without report pages or print controls when not ready; bulk printing filters out pending sheets. Individual and bulk server routes fetch the name-free student projection and the official key once each, including only the latest submission fingerprint (no responses or original files). Student details reuse its existing key/submission fetch.
