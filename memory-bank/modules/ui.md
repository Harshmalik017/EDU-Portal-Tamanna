# Module: UI
Layout: `components/layout/AdminShell` owns desktop collapse and mobile drawer state; `Sidebar` and `TopBar` share it. The top bar toggles between the full desktop sidebar and an 80px icon rail, or opens the mobile drawer. The rail keeps all navigation links, active indicators, tooltips, and accessible names; content and loading overlays reserve its width. Closed mobile menus are hidden from keyboard navigation; the mobile drawer traps focus, supports Escape, restores focus, and releases scroll locking when closed or resized to desktop. `app/admin/layout.tsx` retains server auth and passes server-rendered page children through the shell. Shared: `components/ui` (Button, Card with header slots, Badge, StatCard, PageHeader, Input, Select, Skeleton, Dialog), `Toast` (useToast), `CameraCapture`, `VersionBadge`.
Admin content and the landing page use the available viewport width with responsive gutters rather than a narrow fixed max width. The mobile sidebar locks background scrolling while open and keeps overflow scrolling within the menu. The landing page uses a hamburger toggle to expand its mobile section menu; selecting a section closes it. Visible demo indicators use a pulse animation that is disabled for reduced-motion preferences. The login page includes Home links in its top bar and footer.
The dashboard omits scan and print shortcuts and no longer prompts for batch hand checks; demo mode is labeled "Demo Data" in the sidebar.
Dashboard performance charts use level-colored legend pills and bar labels, with student counts listed beneath each bar.
The desktop Student Reports table uses a brand-green header and clear cell borders; it stays horizontally scrollable when needed.
Sidebar surfaces use the Tamanna green palette. Student Reports actions include Report, Profile, OMR Sheet, and delete. There are no hand-check actions.
The blue OMR Sheet action explicitly removes the soft clay background image so its white text sits on solid dark blue, not the inherited pale gradient.
Admin pages show an icon before each page title. Mobile admin screens have a fixed bottom navigation for Dashboard, Check Sheets, and Student Reports; the Check Sheets action is centered in a raised round button. Dashboard performance charts display in two columns on wider screens.
Show "Uttar Pradesh" beneath the Tamanna logo across the portal and identify Uttar Pradesh in the landing-page programme label.
The landing page omits the former In schools workflow and guide-credit section.
Student Reports has no verified/mismatch/excluded count cards or verification badges. Profile and roll-number buttons open a details-only dialog, without a scorecard or sheet fetch. Class and gender appear as blue and violet pills below names instead of separate columns. A single blue OMR Sheet button opens originals and editable themed circles. For uncertain copies, Review Pending appears on a smaller second line inside that button; no Review scan / Confirm blurry answers label appears below it. There is no separate Check column or duplicate sheet action. Each section shows Section Score on the first line and a colored STEN SCORE pill on the second. Blurry sections retain known-answer marks, without final Sten; per-section provisional/blurry lines are omitted. The legend and score tooltip still distinguish provisional marks. Confirm and score saves final marks only after every uncertain answer is corrected. Mobile cards use the same pills, sheet action, and score layout.

Individual Report links open a name-free dialog at the existing report URL. Its top-corner Hindi/English selector starts in Hindi; all report content and printing switch together. Names remain in admin lists and profiles, but the Excel-compatible CSV has no Name column or student-name values. CSV uses UTF-8 with a BOM. Shared dialogs support a header action slot, explicit focus cycling/restoration, and report-only print expansion.
Report links use the admin intercepted `@report` slot with scroll/prefetch disabled. The original page remains mounted; closing restores its state rather than reloading results. Direct report URLs keep a results fallback. Report dialogs are capped at 820px rather than the 1600px sheet width. Report body/print text is larger and the paper height is used more fully.
The themed sheet omits names in its header/export, provides direct M controls with a top-right legend, and uses light-red MULTI rows and stronger bordered amber review rows. OMR Sheet buttons are green for non-excluded copies with all seven sections free of uncertainty, blue otherwise.
Results replace both numeric lines with Section not filled for wholly blank sub-tests on desktop/mobile, based on explicit blank counts rather than zero marks. Report links and the green sheet state share current-key/final-score readiness. Hide Report on pending student-detail pages, omit pending sheets from bulk printing, and show a review prompt for direct report URLs that are not ready.
Dialogs load on demand and share `components/ui/Dialog.tsx` for modal focus, Escape/backdrop closing, and scroll cleanup. Wide sheet dialogs allow up to 1600px. The comparison reserves a full 760px for the theme when space permits and stacks the panels otherwise; container-responsive sheet columns avoid horizontal scrolling. The old editable Check marked answers table is replaced by circle editing in the theme, including on the standalone student page. In-flight sheet reads abort on close; writes disable editing and closing until completion. Report and print links disable prefetch. Sidebar navigation immediately displays a skeleton while the destination page loads.
Dashboard summary cards span three equal columns on wider screens, matching the full-width card layout on Student Reports. The demo banner reads "Demo Data Mode: showing sample student records."
Routes: `/admin` dashboard, `/admin/results` (student reports and scan correction), `/admin/students/[id]`, `/admin/scan` (check answer sheets), `/admin/key` (answer key), `/admin/logs` (dedicated activity logs with six categories and server pagination), `/admin/settings` (account profile and password). The old `/admin/verify` route redirects to Student Reports.
