# Module: OMR (`lib/omr/reader.ts`, `lib/omr/template.ts`)
- Image is resized to 924×1300 reference space; each option is sampled in a radius-4 inner disk to avoid the printed bubble ring and option letter. A sample is marked when its mean gray is below 175, at least 20 gray levels below the row baseline (the third-lowest of four option means), and its pixel variance is below 5000.
- Template coordinates support horizontal drift per vertical pixel: `x = xA + optionIndex * xStep + xSlope * (y - y0)`. This shared geometry keeps reading, overlays, crops, and calibration aligned on skewed scans.
- The default template keeps the supplied scan's calibration. A saved template from before `xSlope` was introduced inherits each column's default slope when loaded, preserving old calibration settings.
- 0 marked = blank, >1 = `MULTI` (flagged, not scored). `UNCERTAIN` is not blank or wrong: it blocks scoring until checked.
- The browser scanner accepts one two-page PDF or captures the two pages sequentially. Extra PDF pages are rejected there; the local batch importer preserves every source page and flags nonstandard page counts.
- Never mask student headers. Browser previews use white backgrounds; uploaded PDFs are stored byte-for-byte, not rebuilt from rendered images.
- Student Reports and student-detail review edit responses directly on the themed OMR circles. A circle selects one A–D answer; each editable row has a visible No response button for an unanswered question. It stores the existing explicit null/blank state, clears any selected answer or review flag for that question, and remains replaceable with A–D or M. The question-number menu and response-table dropdown also call this state No response. Missing rows remain uncertain when another answer is edited. The read-only scanner response table remains available. No response buttons are omitted from read-only sheets and PDF exports.
- Each editable question also has a direct M control for the existing MULTI state. Selecting A–D replaces M; this does not store individual combinations of bubbles or change scoring. M rows have a full light-red background, uncertain rows have a stronger amber background/border, and the top-right legend reads M = Multi select. The former circle-editing helper line is removed.
- The themed header identifies sheets by roll only. Names and name placeholders are absent from both themed pages and their PDF export; originals and admin-only dialog titles remain unchanged.
- The scan and Student Reports show originals alongside a themed OMR preview. Both themed pages use up to 760px and four columns where space permits, two columns in smaller containers, and one column on narrow phones. Bubble sizes do not shrink; question/status cells do not push options out. PA spans two columns when available. Wide dialogs allow 1600px and reserve 760px for the theme in side-by-side mode; smaller comparisons stack instead of scrolling horizontally. The subtitle has no page suffix; page pickers identify the selected page and remaining review counts. Review starts on page two when only that page has uncertain answers.
- Export PDF opens a new print document containing both read-only themed pages and their styles, then the native Print / Save as PDF dialog. Print forces the four-column layout and both PA columns independently of the current screen width. It reuses loaded response/key props (including unsaved edits), not another data request; editing controls are not exported and originals remain unchanged. No external PDF service or rasterization is used.
- Correct responses are green, incorrect responses light red, keyed options outlined green, and uncertain responses amber. Without a trusted key, selected responses are blue rather than guessed correct/incorrect.
- Local `readCopy` finds printed bubble groups across five grayscale thresholds and flags disagreements, faint marks, incomplete columns, and irregular spacing. Keep its layout values in `template.ts`; preserve the browser's calibrated reader separately.
- Batch reading covers the full lower answer area, clusters columns against their median instead of a stray footer glyph, and selects the 30-row answer rhythm instead of blindly taking the final 30 quartets. Practice rows, footer text, and duplicate reconstructed rows must not shift question numbering. A locally unalignable column remains uncertain without discarding other identified columns. A page whose four columns cannot be identified stays uncertain.
- `rescanPages` requires two complete reference-sized page buffers and represents every one of the 240 positions, including both PA columns. Unknown positions never become blank. `check:rescan` covers lower-page answers, skew, stray footer quartets, practice rows, both PA columns, and unreadable/missing pages; `check-rescan.ts` also accepts a private page image, side number, and optional overlay output for diagnosis.
- Use `check:omr` for calibrated detector thresholds and `check:import` for synthetic adaptive reading, uncertainty, key validation, roll assignment, and scoring. No real student scans are test fixtures.
- The themed answer editor calls atomic `review_copy`; browser scanning calls `score_copy` after saving responses. Both use a fingerprint of the exact key shown to the admin. The current UI has no hand-check actions. Legacy verification columns remain for compatibility; do not treat them as scan readiness. Results show known-answer marks with Review Pending inside the OMR Sheet button for uncertain copies; per-section blurry labels are omitted, and final Sten remains withheld. Final scoring still rejects uncertainty, and editing is disabled during saves.
- OMR Sheet buttons become green when all seven section results exist with zero uncertainty and the copy is not excluded. They remain blue for missing, pending, or excluded copies. Successful Confirm and score refreshes the compact server results without losing table state. Green denotes no remaining answer review, not a human-verification stamp.
- Green readiness and Report links also require all seven persisted final scores and a current-key latest submission. Report links are hidden until this condition is met. Entirely blank sub-tests show Section not filled in results without numeric/ Sten scores; missing or uncertain answers are not blank. PA counts all 60 answers, so one blank PA column does not label the full sub-test unfilled.
## Known limits / TODO
- **Template values are calibrated against the supplied scan; other scanner formats may need calibration.**
- Detection thresholds were calibrated against the supplied scan, not a representative set of scanners or camera photos. Review overlays and manually correct uncertain reads before saving.
- No perspective correction: photo must be flat and cropped to the page edges. Add corner markers + warp (OpenCV.js) next.
- Practice questions are not scored. PA has 60 questions across two columns.
- Debug overlay (v0.2.0) is the calibration tool: if circles miss the printed bubbles, adjust `lib/omr/template.ts`.
- Quality thresholds in `checkQuality` are starting values; tune on real photos.

## Calibration (v0.3.0)
`/admin/calibrate` edits the layout and stores it in `settings` (key `template`). `lib/omr/template.ts` holds the defaults used when nothing is saved.
The default coordinates now match the supplied two-page scan. Recheck new scan sources with the debug overlay before changing schools or scanner formats.
