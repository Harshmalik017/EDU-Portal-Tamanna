# Module: Data
Supabase stores `students`, `submissions`, `answer_keys`, `scores`, and `settings`; RLS uses `is_admin()`. Files live in private `sheets` storage and are opened with expiring signed URLs.

- Student `name` and `roll_number` are separate. A one-time migration moves legacy roll values from `name`, leaving names empty for review. School/class/roll and import hashes prevent duplicate imports.
- Keep school, block, district, class, gender, source filename, and review issues. Names proposed from filenames and demographic defaults need human checking.
- Submissions keep response JSON, page-image paths, `pdf_path`, source SHA-256, and the scoring-key fingerprint. Read older PDFs stored inside `image_paths` too.
- Originals are uploaded unchanged. No masking, redaction, public student files, or real student manifests in Git.
- `import_copy` atomically creates a student and submission. `score_copy` validates all 240 official answers and complete responses, rejects uncertain marks and stale keys, and saves all seven scores transactionally. `review_copy` updates checked responses and scores together; failed reviews roll back.
- Key edits invalidate scores and hand verification. Class/gender edits reset verification and change the booklet norms.
- `getKey` fetches the key once. `keyHashOf` fingerprints that exact snapshot, matching SQL `answer_key_hash`; scoring cannot silently use a newer key than the displayed one.
- Results call admin-only `scan_results()` on the server. SQL aggregates the latest saved responses against a validated 240-answer key into per-section correct and uncertain counts. Only compact student rows leave the database; no submissions, keys, or file URLs reach initial results props. A section with uncertain answers is provisional and has no final Sten interpretation; do not persist provisional values into `scores`.
- Results also return explicit `blank` counts (only present JSON-null answers, never missing/unreadable rows) and `report_ready`. Readiness requires seven final scores, zero uncertain answers, the current official-key fingerprint on the latest submission, and a non-excluded sheet. A completely blank section is identified by its exact 30/60-question blank count; zero correct answers alone is not evidence of an unfilled section.
- `check:results` covers blank labels, PA's full 60 answers, and report/action gating. `check:results:database` validates blank/missing/uncertain/MULTI and current-key/final-score readiness in rolled-back synthetic transactions, including permission denial. Add `-- --apply` to install only the results RPC from `portal-update.sql`; this does not rewrite student answers or scores.
- `/api/admin/students/[id]/sheet` checks the signed-in user and admin role, loads only the latest submission plus key, and signs that student's files. Responses are private/no-store; cancellable queries follow the dialog's request signal.
- Signed results are checked for missing entries, errors, empty paths, and null URLs, then normalized to non-null strings before creating image/PDF links. Invalid signing results fail explicitly rather than returning partial or nullable image links.
- Local scripts prepare, upload, reconcile, and score resumably. Keep manifests outside the repository. No import is a hand check.
- Batch preparation accepts `--after-roll <five-digit roll>` to continue a new private manifest after an existing student. The boundary is saved and cannot change on resume; upload still checks live roll collisions and source hashes. Filename underscores become spaces in proposed names. Check gender against handwriting; blank or unclear headers use Not specified, never a name-based inference.
- For confirmed front-only single-page batches, private operator preparation can retain the first-side readings while representing every missing NA, SA, and PA answer as UNCERTAIN. Preserve the one-page original, flag the missing back, and withhold final scores/reports. Do not invent a second source page or coerce missing/unsupported written classes to Class X.
- `scripts/rescan-copies.ts` inventories the 129 existing students, snapshots latest submissions and original scores privately, and prepares both PDF sides without importing new students. Source checksums are verified; cached originals avoid duplicate preparation downloads. Non-two-page originals are retained and explicitly marked Review Pending rather than assigned guessed answer sides. Preparation does not write live answers.
- `supabase/rescan.sql` adds the admin-restricted transactional `rescan_copy` RPC; database setup includes it. Apply locks the official key/student/latest submission and checks the snapshot responses, source hash, key fingerprint, and demographics. A rescan intentionally replaces manual answers, resets verification/manual-score state, and clears stale final scores atomically. Only complete eligible copies get all seven final scores; uncertain copies keep provisional results through `scan_results()` and no saved final scores. Existing identities, exclusion status, and original file paths stay unchanged.
- Rescan commands: `npx tsx scripts/rescan-copies.ts inventory|prepare|apply|verify|summary <private-folder>`; use `prepare --reread` only before any apply, and `install --apply` to install only the additive RPC. Run `check:rescan:database` for rollback-only synthetic transaction checks. Keep the private run snapshot for recovery; never commit it or the PDFs.
- Results CSV is defined in `lib/tamanna/export.ts`: 11 escaped columns matching table data (Roll no., Name including class/gender labels, School, seven test cells, OMR sheet status). Each test cell contains the displayed Section Score/STEN or Section not filled; no hidden metadata or action buttons are exported. Uncertain/excluded sections withhold final Sten interpretation. The browser adds a UTF-8 BOM for Excel and revokes the download URL. `check:export` covers column parity, alignment, quotes, blanks, and uncertainty.
- `replace_copy` in `supabase/rescan.sql` validates admin access, active student, current key, expected latest submission/answers/paths, and private replacement files, then reuses `rescan_copy` to clear stale scores and re-evaluate atomically. New scans for existing no-scan students use the same flow. Browser uploads unique paths before the transaction and removes old files only after success; ambiguous saves never delete possibly committed uploads. Failed old-file cleanup offers an explicit retry. Install only these additive RPCs after rollback checks with `npm run check:rescan:database -- --apply`.
- v0.17.0 rescan was applied and reconciled for all 129 students: 2 fully scored, 127 Review Pending. The 129 stored PDFs contain 259 source pages because one original has three blank pages; it was retained and flagged for replacement rather than given inferred answers. Every expected answer position is represented, including uncertainty. Original files, identities, demographics, and exclusions were preserved; manual response corrections were intentionally replaced.
- `supabase/portal-update.sql` adds the scan-results RPC and `activity_logs`. Run after the base schema; `npm run setup:database` includes both files. Logs have admin-only SELECT RLS and no direct browser write/delete grants. Restricted database triggers record changes; an admin-checked RPC records client-reported account actions. Never record response JSON, keys, passwords, tokens, or settings values.
- Backfill historical uploads once using their submission ID/timestamp. Do not invent historical edits. Log pagination counts matching rows, clamps out-of-range pages by redirect, and fetches only 25 entries ordered by timestamp and ID.
- The base schema and portal update were applied to the configured school project on 2026-10-29 for v0.15.0. Migration execution succeeded; runtime checks remain manual under the user's lint-only instruction.
- Do not seed `supabase/answer_key.sql`: its old example rows are not the official key. Review and upload the supplied official key with `copies:key`.

## Student lifecycle
- `supabase/student-lifecycle.sql` adds nullable archive timestamps and purge leases. Admin-only `archive_students(uuid[],boolean)` applies each archive/restore selection atomically. Restore is permitted strictly before 30 days; archiving does not remove submissions, scores, or private files.
- Active results, dashboard, report queries, and sheet reads omit archived students. `archived_students()` returns compact archive metadata without responses or file URLs. Submission/score triggers lock the parent and reject archived writes, preventing review/archive races.
- `student_roll_counter` has admin-read RLS and no authenticated write grant. Its serialized insert trigger assigns omitted rolls after the highest existing roll, starting at 10001, and tracks explicit import rolls. A permanent high-water value survives deletions; roll updates are rejected. Failed browser saves may consume a roll. Private batch manifests keep their explicit import identities.
- Daily `.github/workflows/cleanup-archive.yml` runs `archive:cleanup -- --apply` at 02:30 UTC. Repository secrets `ARCHIVE_SUPABASE_URL` and `ARCHIVE_SUPABASE_SERVICE_ROLE_KEY` are server-only. Automatic claiming requires service_role and a 30-day expiry. Purges lease records for 15 minutes and verify private storage is empty before cascading database deletion. Delete Storage files through its API, never SQL. Failures are explicit and retryable; audit logs remain.
- `check:archive` covers exact expiry, file-first deletion, storage chunks, invalid paths, and failed cleanup. `check:archive:database` uses rolled-back synthetic records for roll allocation, no reuse, immutable rolls, archive/restore, preserved scores, active filtering, atomic batches, expiry, leases, cascade deletion, and permissions. `-- --apply` installs only the lifecycle and dependent RPC updates and verifies existing identities/submissions/scores are unchanged.

## Archive clearing and activity identities
- Admin-only `claim_selected_student_purges(uuid[])` validates and locks the entire selection before permitting early permanent deletion. Active, missing, or leased records reject the batch. Browser actions use the signed-in admin's existing Storage permissions, never a service credential.
- Manual deletion and scheduled cleanup share the file-first worker. `finish_student_purge` accepts an admin or expired service claim and refuses rows while owned files remain. Failed manual deletion releases its lease for immediate retry but retains its token; `archived_students()` exposes `deletion_pending`, and restoration stays blocked after any deletion attempt starts.
- Activity logs snapshot student name, gender, and roll at each event and retain those fields after permanent deletion, including cascading sheet/score removals. Existing logs can backfill only from students still present; unavailable names/genders stay unrecorded. No historical event is invented.
- The logs page fetches 25 compact events on the server, formats familiar activity/section/settings labels, and puts IST date/time last. `check:results` covers wording, identity fields, unknown history, and column order; archive database checks cover retained identities, explicit deletion, retries, storage guards, and permissions.
